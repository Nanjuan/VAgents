Building MCP servers for VAgents

MCP tools run as separate processes (usually stdio). The agent never gets a shell — each tool is a small, explicit capability you define in Python.

How it fits together

  • Your MCP server — a Python script using FastMCP that exposes @mcp.tool() functions.
  • mcp_servers.yaml — registers how to start the server (command, args, timeouts, approval).
  • profiles.yaml — each agent profile lists which servers and which server.tool names are allowed.
  • Tool gateway — when the model requests a tool, VAgents routes it through the gateway to your MCP process (see app/tools/gateway.py).

Minimal FastMCP server

Put new servers under app/mcp_servers/examples/. Pattern:

from mcp.server.fastmcp import FastMCP

mcp = FastMCP("my-server-name")

@mcp.tool()
def my_tool(arg: str) -> dict:
    """Docstring becomes the tool description for the model."""
    return {"status": "success", "echo": arg}

if __name__ == "__main__":
    mcp.run()

Run manually to verify it starts: python app/mcp_servers/examples/your_server.py

Register in mcp_servers.yaml

Add a block under mcp_servers::

my_server:
  enabled: true
  description: Short human-readable description
  transport: stdio
  command: python
  args:
    - ./app/mcp_servers/examples/your_server.py
  env: {}
  allowed_profiles:
    - cybersecurity_agent
  require_approval: true
  timeout_seconds: 60
  tool_output_limit_chars: 20000

Use command: python so VAgents resolves it to the same interpreter as the app (see MCP client manager). For HTTP remote MCP, use transport: http and url: instead of command/args.

Allow tools in profiles.yaml

For each profile that should use the server:

  • Add the server key to allowed_mcp_servers (e.g. my_server).
  • Add each tool as server_name.function_name in allowed_mcp_tools — function names match your Python @mcp.tool() defs.

Using the Tools tab in the UI

  1. Open Tools in the sidebar.
  2. + opens the form to add or edit YAML-backed servers (same fields as above).
  3. Select a server → Discover tools to confirm the process starts and list tools.
  4. Use the toggle to enable/disable a server.

REST API: GET /api/mcp/servers, POST /api/mcp/servers?name=..., etc.

Safety

app/config/safety.yaml restricts which executables may launch MCP stdio servers (e.g. python, node). That is separate from what your Python code does inside the server.

Prefer capability-based tools (HTTP via httpx, file reads with path checks) instead of subprocess shells or arbitrary commands.
